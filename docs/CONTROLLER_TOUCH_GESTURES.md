# DualSense 触摸板手势

核对日期：2026-10-02。依据为 Sony 官方 PC 支持指南、SDL 官方接口及本项目使用的 SDL 2.28.4 后端。本文件区分硬件提供的数据与本软件识别的手势；源码依据不代表全部连接方式已经实机验证。

## 官方接口能提供什么

Sony 支持 DualSense 在 Windows 10 / 11 上通过 USB 或蓝牙连接，具体功能取决于应用。该指南没有承诺 Windows 自动为触摸板提供桌面手势。[Sony PC 支持指南](https://www.playstation.com/en-us/support/hardware/pair-dualsense-controller-bluetooth/)

| 接口 / 数据 | 用途 |
| --- | --- |
| `SDL_GameControllerGetNumTouchpads` | 查询触摸板数量；不能用设备名称替代实际能力查询。 |
| `SDL_GameControllerGetNumTouchpadFingers` | 查询某块板最多同时支持的触点数量，并非当前接触数量。 |
| `SDL_GameControllerGetTouchpadFinger` | 读取指定槽的接触状态、坐标和压力字段；成功返回 0，失败返回负数。 |
| `SDL_ControllerTouchpadEvent` | 提供接触、移动、离开的事件以及设备实例、槽编号和毫秒时间戳。坐标归一化为 0～1，原点在左上。 |

这些触摸查询从 SDL 2.0.14 起可用。[触摸板数量](https://wiki.libsdl.org/SDL2/SDL_GameControllerGetNumTouchpads)、[同时触点容量](https://wiki.libsdl.org/SDL2/SDL_GameControllerGetNumTouchpadFingers)、[触点状态](https://wiki.libsdl.org/SDL2/SDL_GameControllerGetTouchpadFinger)、[触摸事件](https://wiki.libsdl.org/SDL2/SDL_ControllerTouchpadEvent)

SDL 2.28.4 的 DualSense HIDAPI 增强模式注册一块板、两个触点槽。USB 完整报告和蓝牙增强报告使用同一触点解析；蓝牙简单报告不含触摸坐标。应用须检测当前连接实际报告的触摸能力。[SDL 增强模式](https://github.com/libsdl-org/SDL/blob/release-2.28.4/src/joystick/hidapi/SDL_hidapi_ps5.c#L717)、[USB / 蓝牙报告分发](https://github.com/libsdl-org/SDL/blob/release-2.28.4/src/joystick/hidapi/SDL_hidapi_ps5.c#L1308)

两项实现边界：这里的 `finger` 是报告槽编号，SDL 不向应用暴露 HID 触点计数器的身份字段；DualSense 的 `pressure` 被后端写成接触时 1、离开时 0，不能据此识别按压力度。[SDL 触点解析](https://github.com/libsdl-org/SDL/blob/release-2.28.4/src/joystick/hidapi/SDL_hidapi_ps5.c#L1196)

触摸板机械按下另有独立的 `SDL_CONTROLLER_BUTTON_TOUCHPAD` 按钮，不能把“轻触”和“按下”当成同一输入。[SDL 按钮定义](https://github.com/libsdl-org/SDL/blob/release-2.28.4/include/SDL_gamecontroller.h#L659)

## 本软件的手势范围

软件基于接触时长、位移、方向及双指位置识别以下动作。这些是应用自身的识别结果。SDL 的控制器触摸事件不直接给出 Windows 桌面手势；SDL 内置多指手势处理接收的是另一类 `SDL_FINGER*` 事件。[控制器触摸事件生成](https://github.com/libsdl-org/SDL/blob/release-2.28.4/src/joystick/SDL_joystick.c#L2865)、[SDL 手势入口](https://github.com/libsdl-org/SDL/blob/SDL2/src/events/SDL_gesture.c#L530)

识别结果提供 **10 种可编辑的映射来源**，双指功能要求当前设备实际支持两个触点。识别后可以直接为该动作设置绑定；普通映射编辑器也可以从来源列表选择，或使用“录入手柄按键或触摸手势”捕获来源。试用和录入只识别输入，不发送绑定的键鼠操作。实机验证范围另见下文。

| 输入来源 | 配置标识 | 识别与触发 |
| --- | --- | --- |
| 单指轻触 | `TP:tap` | 短暂接触后离开，等待双击窗口后触发一次。 |
| 单指双击 | `TP:double_tap` | 同一区域连续轻触两次，只触发双击，不补发轻触。 |
| 单指按住 | `TP:hold` | 保持接触达到 0.55 秒时触发一次。 |
| 单指上滑 | `TP:swipe_up` | 0.75 秒内沿主要方向上滑，离开后触发一次。 |
| 单指下滑 | `TP:swipe_down` | 0.75 秒内沿主要方向下滑，离开后触发一次。 |
| 单指左滑 | `TP:swipe_left` | 0.75 秒内沿主要方向左滑，离开后触发一次。 |
| 单指右滑 | `TP:swipe_right` | 0.75 秒内沿主要方向右滑，离开后触发一次。 |
| 双指轻触 | `TP:two_tap` | 两指近同时接触后离开，触发一次。 |
| 双指向上滚动 | `TP:scroll_up` | 两指向上滑动，每经过一格距离触发一次绑定。 |
| 双指向下滚动 | `TP:scroll_down` | 两指向下滑动，每经过一格距离触发一次绑定。 |

单指鼠标是独立的连续输入模式，滑动产生 Windows 鼠标相对位移，不属于上述 10 个一次映射来源。双指“直接滚动”开关可以让未绑定的方向输出普通滚轮；启用手势后，该方向已有自定义动作时优先执行绑定，避免重复滚动。触摸板机械按下也保持独立的物理按钮映射。

通用设备设置的手势、单指鼠标和直接滚动默认关闭。《无限暖暖》v3 在真实触摸能力可用时安装相应手势绑定，推荐开启手势、关闭单指鼠标和直接滚动，灵敏度为 40%；双指滚轮直接由两个滚动来源的绑定输出。首次安装该触摸布局启用手势一次，并保留已调整的鼠标模式和灵敏度；之后所有选项随设备保存，用户关闭手势后不会在后续启动时自动重新开启。

开关与识别灵敏度随设备保存，各手势动作随该设备的映射预设保存。手势是独立输入，不与物理按钮组成组合键，只设置一个触发动作。识别灵敏度调节轻触容差、滑动距离和滚动步长，不改变上述时间阈值。

轻触最长接触时间为 0.25 秒。为区分双击，单次轻触会等待最长 0.28 秒的第二次接触窗口；双击成立时取消待发的轻触。这里的“按住”指一次识别动作，映射为键盘 / 鼠标按键时仍使用有限时长的按下与释放，未实现按住拖拽。

捏合和旋转可从双指几何变化推导，本轮未开放这些动作。三指手势和压力手势不属于该硬件数据路径。

手势编辑器配置键盘、鼠标和截图等快捷动作，只处理本软件读取的输入和本软件发送的动作，不改写手柄固件，也不把 DualSense 注册为系统精密触摸板。

## 《无限暖暖》v3 的触摸布局

单指左滑衣柜 C、右滑背包 B、上滑任务 U、下滑地图 M，四个常用菜单直接打开；对应的 Create + 面键短按入口让位，原来的服装进化、奇想手账和设计图长按入口保留。没有对应触摸来源的手柄继续使用完整 Create / View 菜单层。

单指轻触 T 用于任务追踪，当前能力下也可能是派生能力 2；双击 P 打开大喵相机，按住 CapsLock 打开功能汇总，双指轻触 V 打开大喵视角。T、U、C、B 等键在不同游戏场景中会复用，实际效果仍以游戏当前提示和游戏内改键为准。双指滚动默认控制鼠标滚轮，可以改成其他每格触发一次的操作。

左摇杆移动与轻推慢走、面键基础行动、L1 能力槽及独立 L2 / R2 鼠标按住继续使用实体按键。完整默认布局、键位来源、阈值及保留用户编辑的升级规则见 [《无限暖暖》布局与按键依据](INFINITY_NIKKI_LAYOUT.md)。这套触摸布局属于本项目设计，不是游戏官方手柄默认键位。

## 识别与配置边界

- 只有当前设备实际提供触摸板时显示入口；需要两个触点的功能还须确认容量至少为 2。设置与当前设备关联，不能给无触摸板的手柄沿用配置。
- 一个触摸过程从接触到全部离开结束。升级为双指后不再补发单指轻点；按下机械按钮时取消轻点候选，避免重复动作。
- 断开、设备切换、能力消失、暂停映射、配置切换和采样失败应取消候选。恢复时若已有手指接触，等待全部离开再开始新的过程。
- 不把槽编号当作跨接触生命周期的永久身份；双指几何变化与位移突变应受到边界保护。
- 时长使用单调时钟；位移和方向阈值须对接触抖动留出余量。双指滚动与捏合须避免同时触发冲突动作。

SDL 在设备断开时也会生成触点离开，因此识别器须区分正常松手与断开取消。[SDL 断开回中](https://github.com/libsdl-org/SDL/blob/release-2.28.4/src/joystick/SDL_joystick.c#L1423)

`GetTouchpadFinger` 提供当前状态快照。同一次输入更新中完成的极短接触可能在下一次快照前结束；若要保留这种接触，须处理按时间顺序的触摸事件，不能以提高 UI 刷新率替代。[SDL 状态查询实现](https://github.com/libsdl-org/SDL/blob/release-2.28.4/src/joystick/SDL_gamecontroller.c#L2265)

当前采样读取 SDL 接触边沿，用本地递增编号区分已观察到的槽位复用；识别器仍使用逐帧坐标快照。更新间隔内已经结束的完整轻触不会被重放，也不能依靠本地编号恢复 SDL 后端没有报告的接触身份变化。

## 验证范围

本轮通过实际 `Device.scan()` / `read()` 读取到 DualSense Wireless Controller：触摸板数量为 1，单板同时触点容量为 2；无人接触时返回空触点列表，采样有效且无读取错误。更新后的 Python 调试窗口还实际显示了“最近识别：双指滚动”。这验证当前连接的双指数据与滚动识别，其余手势及 USB / 蓝牙切换尚未逐项人工验证。

自动化测试分别覆盖 SDL 采样与槽位复用、手势识别、映射端到端输出及设备设置持久化。已经验证单击延迟、双击排他、四向滑动、按住的有限释放、双指滚动、预览不发送系统输入、机械按下独立，以及暂停、断开、设备 / 配置 / 容量变化和读失败的取消。

配置界面提供实时识别预览：直接显示接触指头数量及最近识别的手势，使用当前灵敏度草稿，不执行任何映射动作。识别后可直接打开该来源的绑定编辑；双指滚动明确区分向上、向下。普通绑定录入也可捕获这些来源。打开编辑时先等待触点全部离开；断开或更换设备后停止预览。

验收需覆盖单指 / 双指接触、各方向滑动、机械按下冲突、手指逐个离开、异常读失败、接触中断开与重连、暂停后恢复、设备配置切换，以及 USB / 蓝牙两种连接。合成输入测试验证识别和取消逻辑；实机测试验证触点数量、坐标连续性和实际操作体验，两者应分别记录。
